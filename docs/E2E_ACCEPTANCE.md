# تستِ پذیرشِ end-to-end (فاز ۱۲ G1)

سناریوی پذیرشِ خودکار که چرخهٔ کاملِ کسب‌وکار را روی **DBِ واقعی** و از طریقِ
**command/queryهای واقعیِ Application** (همان مسیری که UI صدا می‌زند) اجرا و هر گام را
PASS/FAIL گزارش می‌کند. هدف: کشفِ زودِ باگ‌های یکپارچگی پیش از فروش.

## اجرا
```
set SAMA_E2E=1
SamaHesab.exe
```
گزارش در `screenshot/e2e_report.txt` و لاگِ `[E2E]` نوشته می‌شود. اپ پس از پایان بسته می‌شود.

## گام‌ها (هر کدام یک Check)
1. **داده‌ی پایه** موجود است (کالا/مشتری/تأمین‌کننده/انبار/سالِ مالی). اگر سالِ مالی نبود، ساخته می‌شود (تستِ خودکفا).
2. **خرید:** `CreatePurchaseInvoiceCommand` — دریافتِ ۱۰ واحد.
3. **موجودی:** پس از خرید باید دقیقاً ۱۰ واحد افزوده شده باشد.
4. **فروشِ نقدی:** `CreateSalesInvoiceCommand` — فروشِ ۴ واحد، پرداختِ کامل.
5. **موجودی:** پس از فروش باید دقیقاً ۴ واحد کم شده باشد.
6. **سندِ حسابداریِ خودکار:** برای امروز حداقل یک سند ایجاد شده باشد (COGS/فروش).
7. **توازنِ تراز:** جمعِ بدهکار = جمعِ بستانکارِ تراز آزمایشیِ امروز.

## آخرین نتیجه (۲۰۲۶/۰۶/۱۶ — DBِ توسعه)
```
[PASS] داده‌ی پایه موجود است — کالا=27 مشتری=40 تأمین=4 انبار=3 سالِ‌مالی=1
[PASS] ثبتِ فاکتورِ خرید — سند #21
[PASS] افزایشِ موجودی پس از خرید — 11 → 21
[PASS] ثبتِ فاکتورِ فروش (نقدی) — سند #66
[PASS] کاهشِ موجودی پس از فروش — 21 → 17
[PASS] سندِ حسابداریِ خودکار برای امروز ایجاد شد — تعداد=2
[PASS] توازنِ تراز آزمایشی — بدهکار=18,000 بستانکار=18,000
خلاصه: PASS=7 · FAIL=0
```

## نکته
این هارنس **داده‌ی واقعی می‌سازد** (فاکتورِ خرید/فروش + سند + گردشِ موجودی با توضیحِ «E2E…»).
روی DBِ تولید فقط برای پذیرشِ اولیه اجرا شود؛ سپس داده‌ی تستی پاک شود.
