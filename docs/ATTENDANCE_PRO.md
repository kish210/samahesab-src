# 🕗 حضور و غیابِ حرفه‌ای (WinKart/WinTask-class) — طرح، تقسیم، هماهنگیِ C1/C2

> به‌خواستِ کاربر (@2026-06-22): حضوروغیابِ فعلی (یک صفحهٔ تک‌روزه) ضعیف است و باید مثلِ
> **WinKart/WinTaskِ علم‌وصنعت** یک **اپلیکیشنِ مستقل (exe جدا)** با ده‌ها فرم باشد.
> HR لِینِ C1 است؛ پس C1 دامنه/اسکیمـا/فرمان، و C2 اپلیکیشنِ مستقل + فرم‌ها + گزارش‌ها + UX.

## وضعیتِ فعلی (موجود)
- **بک‌اند (C1، خوب):** `AttendanceRecord`/`Shift`/`Holiday`/`LeaveRequest` + فرمان‌های `UpsertAttendance`/`MarkBatch`/`RequestLeave`/`DecideLeave`/`ImportAttendance` + کوئری‌های `GetAttendance(روز)`/`GetAttendanceReport(ماه)`/`GetMonthlyAttendance(کارمند/ماه)` + موتورهای خالصِ `AttendanceCalculator`/`LeaveBalanceCalculator` (C2).
- **UI (ضعیف):** فقط یک صفحهٔ `AttendanceView` (تردد یک روز + علامت‌گذاریِ دسته‌ای). **exe مستقل ندارد.**

## مدلِ WinKart/WinTask (آنچه باید باشد)
1. **مدیریتِ دستگاه‌های تردد** (اثرانگشت/کارت/چهره): تعریفِ دستگاه، اتصال (TCP/USB)، خواندنِ ترددِ خام، همگام‌سازیِ پرسنل. ⏸ نیازمندِ دستگاه/SDK (مثلِ کارت‌خوانِ POS) — لایهٔ انتزاعی + ایمپورتِ فایل تا آن زمان.
2. **پرسنل + تخصیصِ شیفت:** هر کارمند → شیفت/گردشِ شیفت + کدِ تردد روی دستگاه.
3. **شیفت و برنامهٔ کاری:** شیفتِ ثابت/شناور/گردشی، تعطیلیِ بینِ شیفت، شیفتِ شب، نوبت‌کاری.
4. **تقویمِ کاری:** تعطیلاتِ رسمی + روزهای کاری + جمعه‌کاری.
5. **ترددِ خام → پردازش → کارکردِ روزانه:** جفت‌کردنِ ورود/خروج، تأخیر/تعجیل، اضافه‌کاری/شب‌کاری/جمعه‌کاری، غیبت، کسرِکار — طبقِ قواعدِ شیفت.
6. **مرخصی و مأموریت:** درخواست/تأیید (ساعتی/روزانه)، ماندهٔ مرخصی، تقویمِ مرخصی.
7. **گزارش‌ها (مفصل):** کارکردِ ماهانه، تردد، تأخیر/تعجیل، اضافه‌کاری، غیبت، مرخصی، کاردکسِ مرخصی، خلاصه به‌تفکیکِ دپارتمان، خروجی به حقوق.

## 🏗 معماری: اپلیکیشنِ مستقل
- **`hozur.exe`** (پروژهٔ `SamaHesab.Attendance`، مثلِ `pos.exe`) → `SamaHesab.exe --attendance`.
- **`--attendance`** در `App.xaml.cs` → پنجرهٔ `AttendanceWorkspaceWindow` (تمام‌صفحه، RTL): سایدبارِ بخش‌ها + ناحیهٔ محتوا (الگوی پوسته، مستقل از شلِ اصلی).
- بخش‌ها: **تردد روزانه · کارکردِ ماهانه · مرخصی‌ها · شیفت‌ها · تقویم/تعطیلات · دستگاه‌ها · ایمپورت · گزارش‌ها**.

## 🗂 تقسیمِ کار
### 💻 C2 (اپلیکیشنِ مستقل + فرم‌ها + گزارش/UX)
- **ATTP-C2-1** لانچرِ `hozur.exe` + `--attendance` + `AttendanceWorkspaceWindow` (سایدبار/محتوا). + نصاب/میانبر.
- **ATTP-C2-2** فرم‌ها روی بک‌اندِ موجود: تردد روزانه (ارتقا) · کارکردِ ماهانه (`GetAttendanceReport`) · مرخصی‌ها (لیست+تأیید `DecideLeave`/درخواست `RequestLeave`) · ایمپورت (`ImportAttendance`).
- **ATTP-C2-3** فرم‌های شیفت/تقویم/دستگاه (روی فرمان‌های C1) + گزارش‌های مفصل (IReportService).
### 🖥 C1 (دامنه/اسکیمـا/فرمان — لِینِ HR)
- **ATTP-C1-1** CRUDِ شیفت + تخصیصِ شیفت به کارمند (+ گردش/شناور) + کوئری‌ها.
- **ATTP-C1-2** CRUDِ تقویمِ کاری/تعطیلات + کوئری.
- **ATTP-C1-3** موجودیتِ دستگاه + ترددِ خام + پردازشِ خام→روزانه (جفت‌سازی، قواعدِ شیفت).
- **ATTP-C1-4** کوئری‌های گزارشیِ مفصل (تأخیر/اضافه‌کاری/غیبت/کاردکسِ مرخصی).

> **ترتیب:** C2 ابتدا اپلیکیشنِ مستقل + فرم‌های روی بک‌اندِ موجود (ATTP-C2-1/2) را می‌سازد (پرشِ فوری از «یک صفحه» به «اپ»)؛ C1 موازی شیفت/تقویم/دستگاه (ATTP-C1-*) را؛ سپس فرم‌های پیشرفته (C2-3) سوار می‌شوند.
> **دستگاهِ سخت‌افزاری:** مثلِ کارت‌خوانِ POS معوقِ دستگاه/SDK است؛ تا آن زمان ایمپورتِ فایل/دستی.
